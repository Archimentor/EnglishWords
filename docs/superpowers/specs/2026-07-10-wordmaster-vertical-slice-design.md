# 영단어 5000 마스터 수직 슬라이스 설계

상태: 승인됨(사용자 권장안 자동 승인 지시)

## 1. 목적

`개발계획.md`, `개발(구조).md`, `개발(문법).md`를 제품 요구사항의 단일 기준으로 삼아, 정적 호스팅에서 바로 실행할 수 있는 학습 웹 앱을 구축한다. 첫 구현은 5,000단어와 1,000구동사를 한 번에 생성하는 대신, 전체 사용자 흐름과 데이터 검증 체계를 실제로 동작시키는 수직 슬라이스를 완성한다. 이후 콘텐츠는 같은 스키마와 검증 절차를 통과시키며 확장한다.

## 2. 선택한 접근

### 권장·채택: React + TypeScript 수직 슬라이스

- Vite 기반 React SPA로 정적 배포한다.
- 메뉴, 상태 복원, 단어장, 문법 탐색, 플래시카드, 6종 퀴즈, 진도·오답 연동을 첫 릴리스에서 끝까지 연결한다.
- 데이터는 JSON과 TypeScript 런타임 검증을 함께 사용한다.
- 초기 콘텐츠는 각 기능과 경계 조건을 검증할 수 있는 대표 데이터로 구성하고, 목표 수량은 검증 리포트에서 명확히 구분한다.

### 검토했으나 채택하지 않은 접근

1. 단일 `index.html` 구현: 초기 속도는 빠르지만 상태·도메인 로직·테스트가 한 파일에 결합되어 장기 요구사항에 불리하다.
2. 5,000단어·1,000구동사 데이터 선구축: 로드맵의 데이터 우선 순서를 가장 엄격히 따르지만, 데이터 품질 검증 전에 대량 콘텐츠가 쌓이고 실제 사용자 흐름 검증이 늦어진다.

React SPA도 최종 산출물의 진입점은 `index.html`이며, 문서가 정의한 정보구조와 정적 호스팅 조건을 유지한다.

문서 간 메뉴 표기가 다른 부분은 상태 전이까지 상세히 정의한 `개발(구조).md`를 우선한다. 따라서 최상위에는 네 레벨과 `문법/학습/퀴즈`를 두고, `단어장`은 선택한 레벨의 컨텍스트 메뉴로 제공한다.

## 3. 범위

### 첫 수직 슬라이스에 포함

- 기초·유치원·초등학교·중학교 레벨과 문법·학습·퀴즈 최상위 메뉴
- 레벨 대시보드, 소설, 단어장 컨텍스트 메뉴
- 문법 A1~C1 노드 탐색과 대표 노드 상세
- 단어와 구동사의 통합 검색
- 세션 큐 생성, 카드 뒤집기, TTS, 5단계 난이도 기록
- 문서에 정의된 6종 퀴즈와 명시적 `다음문제` 진행
- 오답 1회 +15%, 연속 2회 이상 +30% 및 다음 3슬롯 우선 노출
- 진도, 오답 노트, 완료·미완료 분류
- 새로고침 후 메뉴와 학습 상태 복원
- 데이터 스키마, 교차 레벨 중복·워드패밀리·구동사 커버리지 검증
- 반응형이며 키보드로 사용할 수 있는 한국어 UI

### 이후 콘텐츠 확장으로 남김

- 검수 완료된 5,000개 전체 단어 항목
- 검수 완료된 1,000개 전체 구동사와 레벨당 250개 분배
- 42개 문법 노드의 완전한 장문 콘텐츠
- 레벨당 모든 목표 단어를 100% 포함하는 수동 소설
- 서버 계정, 여러 기기 동기화, 관리자 CMS

수량이 목표에 미달한 개발 데이터는 성공으로 위장하지 않는다. 검증기는 `development` 모드에서 구조 품질을 검사하고, `release` 모드에서 정확한 목표 수량과 100% 커버리지를 추가로 강제한다.

## 4. 아키텍처

### 프레젠테이션 계층

- `AppShell`: 브랜드, 최상위 메뉴, 컨텍스트 메뉴, KPI, 반응형 2열 레이아웃
- `Dashboard`: 레벨별 진행률과 완료·미완료·오답 요약
- `Wordbook`: 단어·구동사 검색과 의미·품사·예문 표시
- `Grammar`: CEFR 레벨, 노드 목록, 노드 상세, 선행 조건 표시
- `Study`: 플래시카드, 난이도 선택, TTS, 세션 진행률
- `Quiz`: 유형 선택, 문제 렌더러, 즉시 피드백, 다음 문제, 결과 리포트
- `Story`: 레벨 소설과 커버리지 상태

화면 컴포넌트는 상태 전환을 요청할 뿐, 샘플링·채점·가중치 계산을 직접 구현하지 않는다.

### 도메인 계층

- `content`: 단어, 구동사, 문법 노드, 소설을 정규화하고 조회한다.
- `scheduler`: 난이도 기본 분포, 오답 가중치, 최소 간격을 결합해 학습 큐를 만든다.
- `quiz`: 6종 문항 생성, 정답 정규화, 즉시 채점, 결과 집계를 담당한다.
- `progress`: 카드 평가와 퀴즈 응답으로 숙련도·오답 은행·통계를 갱신한다.
- `persistence`: 버전이 붙은 로컬 상태를 안전하게 저장·복원·마이그레이션한다.
- `validation`: 파일 내부와 파일 간 데이터 불변식을 검사한다.

도메인 모듈은 브라우저 API에 의존하지 않는 순수 함수 중심으로 작성해 직접 단위 테스트할 수 있게 한다.

### 데이터 계층

웹에서 직접 읽는 정적 콘텐츠는 `public/data` 아래에 둔다.

- `wordlists/{기초,유치원,초등학교,중학교}.json`
- `phrasal-verbs/top-1000.json`
- `phrasal-verbs/by-level/*.json`
- `stories/*.json`
- `grammar/nodes.json`
- `schema/*.schema.json`
- `engine/{difficulty,reprioritize,spacing}-rules.json`

문서의 두 경로 표기(`data/content/...`와 `data/...`) 중 웹 정적 자산 관례와 최종 파일 트리에 맞춰 `public/data/...`를 정규 경로로 선택한다.

## 5. 상태와 데이터 흐름

1. 앱 시작 시 콘텐츠를 검증하여 정규화하고, 저장된 상태의 버전을 확인한다.
2. 상태가 유효하면 메뉴·레벨·진행도를 복원하고, 손상되었거나 오래된 상태는 안전한 기본값으로 마이그레이션한다.
3. 학습 시작 시 레벨 단어와 구동사, 숙련도, 오답 은행을 합쳐 가중치 큐를 생성한다.
4. 카드 평가마다 숙련도와 노출 기록을 즉시 저장한다.
5. 퀴즈 답변은 즉시 채점되지만 사용자가 `다음문제`를 누를 때만 이동한다.
6. 오답은 오답 은행과 학습 가중치에 즉시 반영되고, 결과 화면은 점수·정답률·유형 분포·틀린 항목을 계산한다.
7. 레벨이나 메뉴를 바꾸어도 현재 진행도와 오답 가중치는 보존한다.

## 6. 오류 처리

- 콘텐츠 파일 로드 실패: 오류 화면과 재시도 버튼을 제공하고 빈 배열로 조용히 진행하지 않는다.
- 개별 잘못된 항목: 개발 환경에서는 구체적인 경로와 규칙을 표시하고 검증을 실패시킨다.
- 손상된 로컬 상태: 백업 가능한 원문을 유지한 채 기본 상태로 복구하고 사용자에게 안내한다.
- TTS 미지원·실패: 학습을 막지 않고 텍스트 발음 안내를 유지한다.
- 퀴즈 생성 후보 부족: 가능한 문제 수를 명시하고 중복 오답 선택지를 만들지 않는다.
- 저장 용량 초과: 현재 세션은 메모리에서 계속 동작시키고 저장 실패를 알린다.

## 7. 테스트 전략

- 순수 함수 단위 테스트: 가중치, 오답 보정, 간격, 셔플, 퀴즈 생성·채점, 상태 마이그레이션
- 컴포넌트 통합 테스트: 메뉴 전이, 카드 플립, 즉시 피드백과 수동 다음 진행, 검색, 복원
- 데이터 계약 테스트: ID 고유성, 레벨 중복 금지, 패밀리 헤드 1개, 의미·예문 수, 구동사 전체/레벨 참조 일치
- 접근성 검사: 메뉴·카드·퀴즈의 키보드 조작과 이름/상태 노출
- 빌드 검증: 타입 검사, 린트, 테스트, 프로덕션 빌드
- 브라우저 검증: 데스크톱·모바일 크기에서 핵심 사용자 흐름을 실제로 실행

모든 행동 변경은 실패하는 테스트를 먼저 확인한 뒤 최소 구현으로 통과시킨다.

## 8. 완료 기준

- 문서의 메뉴와 사용자 플로우가 실제 브라우저에서 끝까지 동작한다.
- 6종 퀴즈가 각각 유효한 문항을 만들고 즉시 채점·수동 진행한다.
- 퀴즈 오답이 다음 학습 큐의 우선순위를 높이는 통합 테스트가 통과한다.
- 새로고침 후 메뉴와 학습 상태가 복원된다.
- 개발 데이터 검증, 단위·통합 테스트, 타입 검사, 린트, 프로덕션 빌드가 모두 성공한다.
- 목표 콘텐츠 수량 미달은 리포트에 명시되며, 릴리스 검증은 목표 수량을 충족하기 전까지 실패한다.

## 9. 비목표

- 검수 없이 자동 생성한 대량 학습 콘텐츠를 완성 데이터로 간주하지 않는다.
- 첫 수직 슬라이스에서 로그인, 서버 데이터베이스, 결제, 소셜 기능을 추가하지 않는다.
- 문서 요구와 무관한 디자인 시스템 또는 범용 프레임워크를 만들지 않는다.
